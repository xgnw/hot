# 全网今日热榜（纯 HTML 版）

46 个平台的实时热榜聚合页。**不需要服务器和数据库**，双击 `index.html` 就能看。

---

## 一、怎么用起来

### 1. 打开页面

双击 `index.html`。此时显示的是随包附带的数据快照，不需要任何环境。

### 2. 更新数据（三选一）

**方式 A · 手动更新一次**
双击 `自动更新.bat`，输入 `1` 回车。

**方式 B · 常驻自动更新（推荐）**
双击 `自动更新.bat`，输入 `2` 回车。窗口保持开启，每 30 分钟自动抓一次，刷新页面就是最新数据。

- 改间隔：编辑 `自动更新.bat` 里的 `set INTERVAL=30`
- 没装 Python：把文件里的 `set PY=python` 改成 python.exe 的完整路径

**方式 C · 系统计划任务（开机自动，无窗口）**
管理员身份运行一次，之后每 30 分钟自动更新：

```
schtasks /create /tn "全网热榜更新" /tr "python.exe \"C:\完整路径\热榜\update.py\"" /sc minute /mo 30 /f
```

命令行直接跑：

```bash
python update.py                              # 抓一次
python update.py --loop 30                    # 常驻，每 30 分钟
python update.py --only weibo,baidu,zhihu     # 只更新指定平台
python update.py --workers 8                  # 提高并发（默认 6，别调太大以免被限流）
python update.py --json                       # 额外导出 hot-data.json
```

## 二、开启页面内实时更新（可选）

不配代理时，浏览器里只有 4 个平台能实时刷新（微博 / 头条 / 抖音 / GitHub），其余用快照数据。配好后 46 个平台全部实时，**不用再跑脚本**。

**部署步骤（约 2 分钟）**

1. 登录 Cloudflare → **Workers 和 Pages** → 创建 Worker
2. 把 `proxy-worker.js` 的**全部内容**粘贴进编辑器，**覆盖掉默认的 `Hello World!` 模板**，点部署
3. 复制 Worker 地址，形如 `https://xxxx.workers.dev`
4. 打开页面 → **设置** → 「CORS 代理前缀」填入：

```
https://xxxx.workers.dev/?url=
```

5. 点「测试代理」，提示"代理可用"即成功

填好后页面会按设定间隔自动拉取全部平台，顶栏状态栏显示更新状态。

**检测失败怎么排查**（浏览器直接打开你填的地址，看返回什么）：

| 看到什么 | 说明 | 怎么办 |
|---|---|---|
| `Hello World!` | 部署的是默认模板，`proxy-worker.js` 没粘进去或没重新部署 | 回到第 2 步重做 |
| 打不开 / 超时 | 该域名在你网络下不可达（`workers.dev` 国内常不稳） | 给 Worker 绑自己的域名（Settings → Custom Domains），填新地址 |
| JSON 且 `ok:false` | Worker 正常，上游被白名单拒绝 | 看 `error` 字段确认目标域名 |
| JSON 且有热榜条目 | 代理正常 | 回页面重测，注意地址末尾别多空格 |

> **安全提示**：Worker 默认开域名白名单（只允许热榜相关域名），**不要**把 `ALLOW_ANY` 改成 `true`，否则会变成任何人都能用的开放代理，可能被刷流量。

不想自建也可填公共代理（如 `https://api.allorigins.win/raw?url=`），但慢、有速率限制，稳定性和隐私都不如自建。

## 三、页面功能

- **自动更新**：顶栏开关控制，间隔可选 5 / 10 / 30 / 60 分钟；页面切后台时暂停，回到前台自动补一次
- **搜索**：顶栏输入关键词，跨全部板块过滤，无匹配的板块自动隐藏
- **深色模式**：设置里切换
- **板块显隐**：设置里逐项开关
- **每板块条数**：设置里调整
- **详情**：点板块右上角「更多 ›」查看该平台完整榜单
- **数据状态**：状态栏圆点表示新鲜度（绿=新鲜 / 黄=偏旧 / 红=很旧），"实时 N 个"表示本次实际拉取的平台数
- **本地缓存**：拉到的数据存进 localStorage，下次打开立即显示（快照只作兜底）

### 调整板块顺序

打开 **设置**，在板块列表里：

- 每行右侧 **⏫置顶 / ↑上移 / ↓下移 / ⏬置底** 按钮直接挪（首项、末项对应按钮自动置灰）
- 也可拖每行左侧的 ⠿ 手柄
- 列表上方**筛选框**输入名称，46 个里快速定位要挪的板块
- 「恢复默认排序」还原；「复制当前排序」导出数组

改完立即生效，存在本机浏览器里。

### 让任何电脑打开都是同一顺序

本机调的顺序只存在本机。要改**默认顺序**让它对所有人生效，改 `index.html`：

1. 编辑 `DEFAULT_ORDER`，按想要的先后调整 pkey
2. **把紧跟其后的 `ORDER_VERSION` 加 1**

第二步是关键 —— 别人电脑里已存了旧顺序，只有看到版本号变了才会重新拉取新默认；否则继续用自己的那份。

不想手抄 pkey：在设置里调好顺序 → 点「复制当前排序」→ 把生成的数组粘进 `DEFAULT_ORDER` → 版本号 +1。

改完跑命令让三处对齐（**不联网**）：

```
python sync_order.py           # 先看会改什么
python sync_order.py --apply   # 真正写回
python verify_order.py         # 验证真的生效
```

### 板块图标

设置 → 板块图标，四选（默认第一项）：

1. **内置源站图标** —— 推荐，46 个图标已内联进页面，离线可用、零外部请求
2. **品牌色圆角块** —— 纯色块，不含文字
3. **网站原始图标** —— 实时联网拉取，失败自动回退色块
4. **不显示图标**

源站换图标了想重抓：

```bash
pip install pillow                 # 仅需一次
python fetch_icons.py              # 联网重抓 + 注入
python fetch_icons.py --no-fetch   # 用本地缓存重新注入（离线可用）
```

## 四、新增平台

在 `update.py` 的 `PLATFORMS` 数组加一行即可，**页面不用改**：

```python
('平台标识', '名称', '图标URL', 序号, ('uapis', '平台标识'))
```

没有专属抓取器的平台一律走 `uapis.cn` 通用接口，`type` 就等于 pkey，页面会自动出现对应板块。

加完后按顺序跑：

1. `python fetch_icons.py` —— 补图标
2. 改 `index.html` 的 `DEFAULT_ORDER`（末尾加新 pkey）+ `ORDER_VERSION` 加 1
3. `python sync_order.py --apply` —— 三处对齐

## 五、发布到 GitHub / 静态托管

纯静态站点，**运行时只要两个文件**：

| 文件 | 说明 |
|------|------|
| `index.html` | 主页面（含全部逻辑、样式、46 个内联图标） |
| `hot-data.js` | 数据快照，`index.html` 通过 `<script src="hot-data.js">` 加载 |

> 两文件必须放在**同一目录**（页面用相对路径）。GitHub Pages 默认根目录，直接传上去即可。

**建议一起发布**（工具链 + 文档，让别人能复现）：
`README.md`、`update.py`、`sync_order.py`、`verify_order.py`、`fetch_icons.py`、`svgify.py`、`pick_best.py`、`verify_final.py`、`layout_probe.py`、`proxy-worker.js`、`自动更新.bat`

**不要发布**（已用 `.gitignore` 排除）：

| 路径 | 原因 |
|------|------|
| `_归档_多余文件/` | 开发期临时脚本 / 验证产物 |
| `__pycache__/` | Python 缓存 |
| `_icons_opt/` `_icons_raw/` `_svgout/` | 图标处理中间产物 |
| `svg源/` `热榜SVG源/` | SVG 源 / 备份 |
| `预览.png` | 本地预览截图 |
| `hot-data.json` | 前端不引用，是 `--json` 的可选导出（如需可取消忽略） |

**上线后怎么更新数据**：本地跑一次 `update.py` 生成新的 `hot-data.js`，commit + push，GitHub Pages 几秒到一分钟内自动生效。配了代理（第二节）的话，访客页面会自己实时拉取，连推送都省了。

**可选**：自定义域名在仓库 Settings → Pages 填并加 `CNAME` 文件；404 页可放 `404.html`。

## 六、常见问题

**Q：双击 `index.html` 后板块显示"暂无数据"？**
`hot-data.js` 没生成或为空，跑一次 `update.py` 即可。

**Q：状态栏一直显示"未配置代理"？**
正常。未部署代理时只有 4 个平台能实时更新，其余用快照数据。按第二节配代理即可全部实时。

**Q：代理填了但"测试代理"失败？**
见第二节的排查表。最常见的两种：把默认 `Hello World!` 模板当成代理部署了（代码没粘进去）；或 `workers.dev` 域名在你网络下不可达（换绑自己的域名）。

**Q：图标显示不出来？**
46 个图标已全部内联进页面，正常不会再有这个问题。某个源站改版取不到图时会自动回退成品牌色圆角块，不会空白。想 100% 稳定就保持默认的「内置源站图标」。

**Q：`update.py` 报某个平台"无数据"？**
第三方接口偶尔限流或改版。脚本会跳过失败的平台，**不会**清空已有数据，下次更新成功会自动补上。若某平台连续多天失败，通常是接口变了，可把它换成 `('uapis', '该平台的type')` 走聚合接口。

**Q：GitHub 趋势拿不到数据？**
GitHub 未登录接口限额为每小时 60 次。更新太频繁（比如 5 分钟一次）可能触发限额，等一小时会自动恢复。

**Q：想保留历史榜单（对比昨天同一时间的排名变化）？**
本版本未包含。可在 `update.py` 里加一个函数：每次写完 `hot-data.js` 后，把当前数据按日期另存一份到 `history/YYYY-MM-DD.js`，页面再按需对比。

## 七、文件说明

| 文件 | 作用 |
|------|------|
| `index.html` | 主页面。单文件包含全部样式与逻辑，**双击即可运行** |
| `hot-data.js` | 数据快照，由 `update.py` 自动生成，不用手改 |
| `update.py` | 抓取脚本，零第三方依赖（只用标准库） |
| `sync_order.py` | 把 `index.html` 的 `DEFAULT_ORDER` 同步给 `update.py` 与 `hot-data.js`，保证三处顺序一致 |
| `verify_order.py` | 验证默认排序真的生效 |
| `自动更新.bat` | Windows 双击运行的入口，可选"更新一次"或"常驻自动更新" |
| `proxy-worker.js` | Cloudflare Worker 跨域代理，部署后浏览器可实时拉取全部平台 |
| `fetch_icons.py` | 图标抓取 + 处理 + 注入（需 Pillow） |
| `svgify.py` / `pick_best.py` | 图标处理的底层模块，被 `fetch_icons.py` 调用 |
| `verify_final.py` / `layout_probe.py` | 图标与布局的验证脚本 |
| `hot-data.json` | 可选导出（加 `--json` 参数时生成），方便别的程序复用数据 |
